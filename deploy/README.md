# Deploy the private beta in Mumbai

The current deployment uses **ECS Express Gateway in ap-south-1**, an AWS-provided HTTPS address, and CodeBuild for the Linux container build. See [LIVE.md](LIVE.md) for the actual resources and customer onboarding. The CloudFormation instructions below are an alternative custom-domain deployment, not the deployed stack.

## What this stack creates

One ECS Fargate service (1 vCPU, 2 GiB per task), an HTTPS Application Load Balancer, DynamoDB with TTL/PITR/encryption, task roles scoped to that table, CloudWatch logs and a 5xx alarm, a WAF IP rate rule, and CPU-based scaling from 1 to 4 tasks. Customer keys are generated by an operator command. The demo routes are disabled in production. No self-service dashboard or billing is included.

This first beta serves widget assets and short-lived animation images through the API. Images are stored as base64 in DynamoDB alongside separate challenge records (small current atlas, below DynamoDB's 400 KiB item limit). At larger volume, move images to S3/CloudFront; TTL deletion is delayed and must not be used as authorization. API reads enforce expiry immediately. Site records and hashed key records have no expiry.

## Prerequisites

1. AWS CLI v2 is installed. Add `$HOME/.local/bin` to your PATH if needed. Install Docker from its official distribution for the local container build, or use an AWS build service after authentication.
2. For an AWS Console account, run `/Users/harshit/.local/bin/aws login --profile afterimage --region ap-south-1` and complete the browser sign-in. For IAM Identity Center/SSO, use `aws configure sso --profile afterimage`, then `aws sso login --profile afterimage` instead. Do not paste AWS credentials into chat.
3. Choose a service domain, e.g. `captcha.your-domain.com`, and validate an ACM certificate for it in Mumbai.
4. Supply an existing VPC, two public ALB subnets in different availability zones, and task subnets with outbound access to ECR, CloudWatch, and DynamoDB. Prefer private task subnets with NAT or the necessary endpoints. Public task subnets also work with `AssignPublicIp=ENABLED`; their security group still permits inbound traffic only from the ALB.
5. Review recurring ALB/Fargate/WAF/DynamoDB/networking costs and set an AWS Budget. No free-tier claim or cost estimate is implied here.

## Build and push

Run from the project directory. Commands below are manual instructions; they have not been executed against AWS.

```sh
export AWS_PROFILE=afterimage
export AWS_REGION=ap-south-1
aws sts get-caller-identity
aws ecr create-repository --repository-name afterimage --image-scanning-configuration scanOnPush=true
```

Set `CAPTCHA_ACCOUNT_ID` to the account ID you verified above. If the repository already exists, reuse it.

```sh
export CAPTCHA_ACCOUNT_ID=YOUR_ACCOUNT_ID
export CAPTCHA_REGISTRY="$CAPTCHA_ACCOUNT_ID.dkr.ecr.ap-south-1.amazonaws.com"
aws ecr get-login-password --region ap-south-1 | docker login --username AWS --password-stdin "$CAPTCHA_REGISTRY"
docker build --platform linux/amd64 -t "$CAPTCHA_REGISTRY/afterimage:beta-1" .
docker push "$CAPTCHA_REGISTRY/afterimage:beta-1"
```

## Create the stack

Substitute your own VPC/subnet IDs and validated certificate ARN. The deployment operator needs permission to create IAM roles and the ECS Application Auto Scaling service-linked role on first use.

```sh
aws cloudformation deploy \
  --region ap-south-1 \
  --stack-name afterimage-beta \
  --template-file deploy/aws-stack.json \
  --capabilities CAPABILITY_IAM \
  --parameter-overrides \
    ImageUri="$CAPTCHA_REGISTRY/afterimage:beta-1" \
    VpcId=vpc-REPLACE \
    PublicSubnets=subnet-PUBLIC_A,subnet-PUBLIC_B \
    TaskSubnets=subnet-PRIVATE_A,subnet-PRIVATE_B \
    AssignPublicIp=DISABLED \
    CertificateArn=arn:aws:acm:ap-south-1:YOUR_ACCOUNT_ID:certificate/REPLACE
aws cloudformation describe-stacks --stack-name afterimage-beta --query 'Stacks[0].Outputs'
```

Create a DNS CNAME for your service subdomain to `LoadBalancerDNS` from the outputs (or a Route 53 alias). Verify `https://YOUR_DOMAIN/healthz`. Root `/` intentionally returns 404 in production; the public entry point is `/widget.js`.

The alarm is visible in CloudWatch but has no notification destination until you attach one. The WAF rule applies to all requests, including verification traffic; tune it for expected customer backend traffic and shared NATs before onboarding busy sites. The image records and customer records are retained if the stack is deleted; CloudFormation retains the DynamoDB table intentionally.

## Provision a customer

Use the `TableName` output. This administrative command uses AWS IAM/SSO credentials; it is not exposed over HTTP.

```sh
APP_ENV=production DYNAMODB_TABLE=YOUR_TABLE_NAME \
  .venv/bin/python -m service.manage \
  --name 'Example customer' \
  --origin https://www.customer.example \
  --hourly-limit 100 \
  --output .local/customer-production.secret.json
```

Register every exact origin needed, including scheme and optional port, by repeating `--origin`. No wildcard domains. Send the public site key and the customer's secret through an appropriate secure onboarding channel. Never embed the secret in HTML or commit the output file. Secrets are random, stored only as hashes by the service, and printed only into a mode-0600 file. Current provisioning has no rotation/revocation UI; operator-managed key lifecycle must be implemented before broad onboarding.

See `INTEGRATION.md` for the customer's implementation.

## Before general availability

Validate automated motion/OCR resistance and human completion rates; replace the 32-word research dictionary; provide an accessible alternative; add account/domain ownership verification, key rotation/revocation, billing, per-customer monitoring, and load tests. WAF/IP quotas and registered origins are abuse controls, not proof of browser identity. Origin parameters can be forged by non-browser clients. The iframe's `frame-ancestors` and `postMessage` checks protect browser embedding; the customer secret protects server-side redemption.

Use unique immutable image tags/digests for releases. CloudFormation's ECS deployment circuit breaker rolls back failed deployments. Keep the last working image available for deliberate rollback. Container build and actual AWS deployment still need validation on an AWS-enabled machine.
